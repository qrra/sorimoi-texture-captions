# 소리모이 · 쇼츠 라이브 자막 0.2

유튜브 쇼츠나 일반 영상을 재생한 뒤 **확장 아이콘 → 이 탭에서 자막 켜기**를 누르는 방식으로 바꿨습니다. 파일을 먼저 넣거나 검수해야 하는 화면은 보조 기능으로 옮겼습니다.

## 0.2 사용법

1. 설치용 ZIP의 `sorimoi-chrome` 폴더를 크롬/웨일 확장 관리에서 로드합니다. 기존 같은 폴더를 설치했다면 확장 관리 화면의 새로고침을 누릅니다. 표시 이름은 **소리모이 · 쇼츠 라이브 자막**, 버전은 **0.2.0**입니다.
2. 유튜브 쇼츠나 영상을 열고 소리가 나도록 재생합니다.
3. 퍼즐 아이콘 → 소리모이 → **이 탭에서 자막 켜기**. 팝업을 닫고 영상을 보면 됩니다. 파일 입력·API 키·Python 서버가 필요 없습니다.
4. 같은 유튜브 탭에서 다음 쇼츠로 넘기면 자막을 초기화하고 재생 중인 영상을 다시 찾습니다. 새 탭이나 페이지 새로고침 뒤에는 다시 켭니다.
5. 끄려면 확장 팝업의 **라이브 자막 끄기**. 오디오 트랙·분석 Worker·오디오 컨텍스트를 정리합니다.

### 무엇이 바로 나오고, 무엇이 기다리는가

- 화면에 이미 표시되는 YouTube 자막이 있으면 그 글자를 즉시 활용합니다. 원래 표시를 가리고 동일한 글자에 소리의 무게와 질감을 적용합니다. 팝업이 YouTube 자막 기능 자체를 강제로 켜지는 않습니다.
- 유튜브 자막이 없는 구간은 **실제 탭 오디오를 Whisper base로 한국어 전사**합니다. 3~5초의 짧은 구간을 후행 처리하므로 단어와 동시에 뜨는 무지연 자막은 아닙니다. 처리 시간도 더해지며 PC마다 다릅니다. 화면에 출처와 후행 인식 상태를 표시합니다.
- YAMNet은 약 1초의 현재 소리에서 효과음 후보를 찾습니다. 잡음·음악·겹친 음성에서 오탐과 누락이 있습니다. 물리적 촉감이나 감정을 측정하는 기능은 아닙니다.
- 음량은 연속 RMS로 반응하고 질감은 소리 분류에 따라 달라집니다. 마이크를 사용하지 않고, 캡처한 오디오를 서버로 전송하지 않습니다.
- 음성·효과음 모델과 JS/WASM을 **설치 파일에 포함**했습니다. 첫 시작의 모델 메모리 초기화 시간은 필요하지만 수백 MB를 따로 다운로드하지 않습니다. 압축 해제 용량은 약 121MB입니다.

### 온소리에서 이어받은 방향과 달라진 흐름

팀원분의 [온소리 0.2 README](https://github.com/NY-colab/onsori-youtube#readme)를 기준으로 사용 흐름을 재검토했습니다. 온소리는 최대 60초 녹음 후 분석 완료 결과를 표시하고 새 영상에서 첫 녹음 연결을 요청합니다. 이번 수정은 **현재 탭에 한 번 연결 → 짧은 구간 반복 분석 → 쇼츠 이동 때 이전 추론 폐기**로 구성했습니다. 핵심 조합은 WXT + Whisper/Transformers.js + YAMNet이며 기존 vtt.js는 파일 검수 기능에 남았습니다. 온소리 저장소의 코드를 복사한 빌드는 아닙니다.

### 검증 범위

로컬 모델의 한국어 합성 음성 전사, 기존 자막 우선 표시, 이동 시 결과 폐기, 음량 분석을 테스트합니다. 테스트 페이지 결과와 실제 설치된 확장의 Chrome `tabCapture`·오프스크린 연결 결과는 구분합니다. 브라우저 보안 정책으로 이 환경에서 사용자 프로필의 확장 등록을 자동 수행할 수 없어 **실제 유튜브 쇼츠에서의 종단 간 검증은 아직 완료하지 못했습니다.** 설치 후 소리 연결 오류가 있으면 팝업에 오류를 표시합니다. 이를 모든 쇼츠에서 검증 완료된 제품으로 표현하지 않습니다.

# 0.1 파일 검수 스튜디오 사용 안내

크롬 MV3 확장 프로그램 0.1.0. 소리를 입자·단단함·물결·숨결·부드러움·무게의 여섯 가지 글자 질감으로 표현합니다. 직접 합성한 체험음, 로컬 소리 분석, WebVTT 대사 가져오기, 사람 검수, 일반 HTML5 영상 위 자막 표시를 연결했습니다.

## 설치

1. 함께 제공한 **sorimoi-chrome** 폴더를 유지합니다. ZIP을 사용한다면 먼저 압축을 풉니다.
2. 크롬 주소창에 `chrome://extensions` → 개발자 모드 → 압축해제된 확장 프로그램 로드 → **manifest.json이 바로 들어 있는 sorimoi-chrome 폴더** 선택.
3. 퍼즐 아이콘 → 소리모이 → **스튜디오 열기**.
4. 웨일에서는 `whale://extensions`에서 같은 방식으로 설치할 수 있습니다. 실제 설치 완료 여부는 별도 확인이 필요합니다.

Chrome 120 이상을 대상으로 빌드했습니다. 서버, Python, API 키가 필요 없습니다. 모델 가중치까지 포함한 약 19MB의 확장입니다. 스토어에 등록된 제품은 아닙니다.

## 먼저 체험하기

스튜디오의 재생 버튼을 누르면 24초짜리 합성 소리와 수동으로 디자인한 질감 자막을 함께 체험합니다. 왼쪽 여섯 팔레트는 해당 구간으로 이동합니다. 움직임은 기본 OFF입니다. 질감 농도, 글자 크기, 대사/소리/상세 정보량, 일반 자막 비교를 조정할 수 있습니다.

체험음은 종이·물 등의 실제 녹음이 아닌 직접 생성한 합성음입니다. 체험 자막은 AI 인식 성능을 입증하는 데이터가 아닙니다. 분석 결과는 원본 소리를 들으며 확인해야 합니다.

## 내 영상에 적용하기

1. 사용 가능한 **5분 이하, 200MB 이하의 오디오·영상 파일**을 스튜디오에서 엽니다. 재생·디코딩 가능한 형식은 브라우저의 코덱 지원에 따릅니다.
2. **소리 결 분석**을 누릅니다. YAMNet을 이 기기에서 실행하며 오디오를 외부로 전송하지 않습니다. GPU를 사용할 수 없으면 CPU로 분석합니다.
3. 대사는 보유한 **WebVTT(.vtt)**를 가져옵니다. 이번 버전에는 자동 음성 전사와 임의 사이트의 자막 다운로드 기능이 없습니다.
4. 목록에서 자막을 골라 글자, 시작/끝 시간, 종류, 질감, 무게를 다듬은 뒤 **수정 · 검수 완료**를 누릅니다. AI 후보는 처음에 미검수 상태입니다.
5. 필요하면 대상 영상 주소를 넣습니다. YouTube는 영상 ID도 비교해 다른 영상에 잘못 적용되는 것을 막습니다. 주소를 비우면 어느 일반 영상 탭에서든 수동 적용할 수 있습니다.
6. **검수 자막 저장** → 원하는 웹페이지 영상 탭 → 확장 아이콘 → **이 페이지 영상에 적용**. 검수된 자막만 표시됩니다. 영상과 입력 파일은 같은 타임라인이어야 합니다.
7. 새 영상이나 새 페이지로 이동하면 다시 적용합니다. 같은 페이지에서 재적용하면 이전 오버레이를 정리합니다. **이 페이지에서 자막 끄기**로 제거합니다.

확장 저장소에는 자막과 설정만 저장합니다. 미디어 파일은 저장하지 않아 스튜디오를 다시 열 때 파일을 재연결해야 합니다. 내보낸 JSON은 질감·검수 상태까지 보존하고 VTT는 텍스트와 시간만 보존합니다. VTT 내보내기에는 편집 중인 후보도 포함됩니다.

## 왜 이 세 가지인가

기준 문서: [소리모이 | 반응형 자막 · 라운드테이블 준비](https://app.notion.com/p/404b2cbd917a8101b616e5f05d9e9f1d). 3개 후보 DB의 11개 항목을 검토했습니다. ‘사전 분석 → 사람 검수 → 확장 표시’와 모션 기본 OFF를 이 시제품에 반영했습니다. 성능 순위를 실측한 결과가 아니라, **서버 없는 범용 확장이라는 이번 범위에 대한 선택**입니다.

| 역할 | 채택 | 이 시제품에서 실제 하는 일 |
|---|---|---|
| 확장 골격 | [WXT 0.20.27](https://github.com/wxt-dev/wxt) | MV3 빌드·팝업·확장 스튜디오. `activeTab`과 `scripting`으로 사용자가 누른 탭에 적용 |
| 대사와 시간 | [vtt.js 0.13.0](https://github.com/mozilla/vtt.js) | 한글 WebVTT 파싱, ms 규격으로 변환. 대사와 효과음을 같은 재생 시간에 연결 |
| 소리 후보 | [YAMNet TFJS/1](https://www.kaggle.com/models/google/yamnet) + TensorFlow.js 4.22.0 | 16kHz mono 음원에 실제 모델 추론, 521종 분류 점수에서 질감에 대응하는 소리 후보 생성 |

다른 후보: Stylus는 스타일 실험용이며 독립 자막 엔진이 아니어서 제외했습니다. subtitle.js는 SRT까지 필요할 때 유용하지만 여기서는 브라우저 WebVTT 경로를 우선했습니다. youtube-transcript-api와 yt-dlp는 Python·비공식 사이트 추출에 의존해 파일 입력 기반 확장에 넣지 않았습니다. faster-whisper는 자동 전사 확장 때의 후속 후보입니다. PANNs·BEATs는 로컬 Python/PyTorch와 추가 통합 비용이 있고, CLAP은 소리 설명 검색에는 유용하나 발생 경계를 직접 주지 않습니다. 향후 ASMR 질감용 데이터로 비교 검증할 수 있습니다.

## 분석과 표현의 구분

YAMNet은 물리적 촉감이나 감정을 측정하지 않습니다. 모델의 소리 라벨을 사람이 정의한 질감 사전에 대응시키는 시각 표현입니다. 소리 크기는 구간 RMS를 정규화해 글자의 무게에 제한적으로 반영합니다. 혼합 오디오에서 개별 소리의 독립 음량을 측정하지는 않습니다.

분석 창은 공식 YAMNet의 약 0.96초, 이동 간격은 0.48초입니다. 인접한 같은 클래스의 창을 합쳐 시작·끝 후보를 만듭니다. 정밀 onset 검출기가 아니며 시간은 사람이 검수해야 합니다. 분류 점수는 보정된 확률·정확도가 아닙니다. 기본 기준은 0.25와 상위 두 클래스 차이 0.035, 낮은 RMS 제외입니다. 음성이 아닌 소리를 보장하지 않으며 오탐·누락이 있습니다. 지원 질감에 대응되지 않는 클래스는 자동으로 글자를 만들지 않습니다.

## 지원 범위와 확인 결과

- 일반 페이지의 가장 큰, 표시 중인 최상위 HTML5 `video` 요소를 대상으로 합니다. 재생·일시정지·탐색·배속은 `video.currentTime` 기준입니다.
- Shadow Root로 페이지 스타일과 자막 스타일을 분리합니다. 전체화면 컨테이너로 오버레이를 이동하는 코드가 포함되어 있습니다.
- 교차 출처 iframe, 닫힌 Shadow DOM, canvas 플레이어, Picture-in-Picture, video 요소 자체의 네이티브 전체화면은 제한될 수 있습니다. 모든 사이트를 실제 검수한 제품은 아닙니다.
- 크롬 내부 페이지, 확장 관리 페이지, Chrome 웹 스토어에는 주입할 수 없습니다. 로컬 `file:` 페이지에는 브라우저의 별도 파일 접근 허용이 필요할 수 있습니다.
- 2026-10-26 확인: 자막/시간/입력검증/분류창 병합 **4개 단위 테스트 통과**, 번들 빌드 통과, 로컬 모델이 실제 `[1,521]` 출력을 반환함을 확인.
- 연결된 Chromium 브라우저에서 체험 화면, 소리 분석(24초 합성음 → 후보 5개, 정확도 평가 아님), 한글 VTT 2개 가져오기를 확인.
- HTML5 CC0 샘플 영상에서 오버레이 재적용 시 1개 유지, 1초 탐색 후 자막 표시, 2배속, 제거 후 0개를 확인.
- 자동화 환경에서 전체화면 요청은 `not granted`로 거절되어 실제 전체화면 검증을 완료하지 못했습니다. 작은 화면 viewport override도 적용되지 않아 모바일 폭은 미검증입니다. 실제 사용자 프로필에 확장을 설치한 뒤의 `chrome.scripting` 경로와 모든 사이트의 호환성은 별도 검수가 필요합니다.

## 개발

```text
npm ci --ignore-scripts
npm test
npm run extension
```

결과는 `.output/chrome-mv3/`. 웹 검수용 `npm run dev`, 웹 빌드 `npm run build`도 제공합니다. `node tests/model-smoke.mjs`는 포함된 가중치의 실제 CPU 추론을 확인합니다. `tests/overlay.html`은 오버레이 검증용 페이지입니다. `package-lock.json`으로 설치 버전을 고정했습니다.

모델 출처: https://tfhub.dev/google/tfjs-model/yamnet/tfjs/1/model.json?tfjs-format=file. 가중치 및 모델은 Apache-2.0이며 공식 [Kaggle 모델 카드](https://www.kaggle.com/models/google/yamnet/tensorFlow2/yamnet/1)에 사용 조건과 입출력이 기재되어 있습니다. `public/models/yamnet`에 원본 가중치·클래스 표·LICENSE를 포함했습니다. 자세한 고지는 `THIRD_PARTY_NOTICES.md`와 `public/licenses`를 확인하세요.
